# تحليل بروتوكول Silkroad Gateway وAgent

## الإطار العام

يستخدم `SCommon/Security/Security.cs` إطارًا يبدأ بـ `UInt16 packet_length` ثم `UInt16 opcode` ثم بايتي Security Bytes ثم جسم الحزمة. عند تفعيل Blowfish، تُضبط أعلى بتة في `packet_length` (`0x8000`) وتُشفّر البيانات من offset 2، أي opcode وSecurity Bytes والجسم، مع حشو صفري إلى مضاعف 8. الخادم يهيّئ Gateway وAgent باستخدام `SecurityFlags.Blowfish | SecurityFlags.SecurityBytes`.

## تسلسل Gateway

1. يتصل العميل عبر TCP إلى `GatewayServerIPAddress:GatewayServerPort`.
2. يرسل الخادم `0x5000` غير مشفّرة، وبايتها الأول يعلن Blowfish وSecurity Bytes، ثم مفتاح Blowfish بطول 8 بايت، و`seed_count` و`crc_seed` بطول 4 بايت لكل منهما.
3. يرسل العميل `0x9000`، ثم يرسل `0x2001` مشفّرة بجسم `WriteAscii("SR_Client")` متبوعًا بالبايت `0`.
4. يرد الخادم بـ `0x2001` وجسم `WriteAscii("GatewayServer")` ثم البايت `0`.
5. يرسل العميل طلب الدخول `0x6102` مشفّرًا وجسمه: `locale: UInt8`، ثم `id: ASCII`، ثم كلمة المرور بصيغة ASCII، ثم `server/shard: UInt16`. ترميز ASCII في `Packet.WriteAscii` هو `UInt16 byte_length` ثم البايتات الخام.
6. قبل بناء الحزمة، يحوّل Gateway كلمة المرور إلى MD5 lowercase hex؛ لذلك يرسل العميل كلمة المرور الخام في جسم `0x6102`، ولا يرسل MD5 بنفسه.
7. رد النجاح هو `0xA102`: `UInt8(1)` ثم `session_id: Int32` ثم عنوان Agent ASCII ثم منفذ Agent `UInt16`. حالات الرفض تبدأ بـ `UInt8(2)` ثم كود الحالة.

## تسلسل Agent بعد نجاح Gateway

1. يتصل العميل بعنوان Agent والمنفذ الواردين في `0xA102`.
2. يكرر مصافحة `0x5000`/`0x9000` والهوية `0x2001`، ويتوقع `WriteAscii("AgentServer")`.
3. يرسل `0x6103` مشفّرة وجسمها `session_id: Int32`، ثم `id: ASCII`، ثم كلمة المرور الخام: ASCII.
4. يرد Agent بـ `0xA103` وجسم نجاح `UInt8(1)`؛ عندها يكون اختبار المصادقة الأساسي قد نجح، مع بقاء تدفق اختيار الشخصية خارج نطاق المرحلة الأولى.

## حدود التنفيذ

يعتمد العميل على نسخة GDScript مولّدة من نفس ثوابت وخوارزمية `SCommon/Security/Blowfish.cs`، وعلى خوارزمية Security Bytes وCRC الموجودة في `Security.cs`. حقلا العنوان والمنفذ قابلان للتعديل في الواجهة لأنهما يأتيان من إعدادات SQL `_ServerConfig` وليس من ملفات المشروع المنشورة.

## Phase 2: Agent character and world flow

بعد نجاح `0x6103`، يبقى اتصال Agent مفتوحًا. يرسل العميل `0x7007` بجسم يبدأ ببايت الوضع: `2` لطلب قائمة الشخصيات، `1` لإنشاء شخصية، و`4` لفحص الاسم. استجابة Agent هي `0xB007`; في وضع القائمة يبدأ الجسم بـ `2, 1` ثم تُرسل الخانات الثلاث، وكل خانة موجودة تبدأ بـ `1` ثم `RefObjID` واسم ASCII والمقياس والمستوى والخبرة والإحصاءات وبيانات العناصر.

لإنشاء الشخصية يستخدم العميل الجسم التالي: `mode=1`، اسم ASCII، `model` بــ 32-بت، `scale` بــ 8-بت، ثم أربعة `RefItemID` بــ 32-بت. يتحقق السيرفر من الاسم والموديل والعناصر عبر `_RefCharGen` قبل استدعاء `_AddNewChar`، لذلك يجب أن تطابق معرفات الإنشاء بيانات قاعدة shard الفعلية.

اختيار الخانة يستخدم `0x7001` مع فهرس الخانة بــ 8-بت. بعد قبول الاختيار يرسل Agent `0xB001` ثم `0x34A5` و`0x3013` لبيانات تحميل الشخصية و`0x34A6` لإنهاء التحميل. البيانات الأولية التي يستهلكها العميل تشمل الموديل والاسم والمستوى والخبرة والذهب وHP/MP. يرسل العميل `0x3012` فارغًا لدخول العالم، ويرد السيرفر بإحصاءات `0x303D` وحالة العالم `0x3077`، وبعدها يمكن إرسال الحركة عبر `0x7021` والتوقف عبر `0x7023`.

تعرض Phase 2 عالمًا إجرائيًا ثلاثي الأبعاد مستوحى من Jangan، وليس أصول Silkroad الأصلية. معرفات النموذج والعناصر في شاشة الإنشاء معرفة كثوابت قابلة للتعديل في `character_select.gd` ويجب مواءمتها مع جداول الخادم قبل اختبار الإنشاء الفعلي.

## Phase 3: Spawn, combat, and loot

يستقبل العميل `0x3015` للـspawn الفردي و`0x3016` للإزالة، كما يستهلك `0x3019` لبيانات spawn المجمعة. بنية الوحش تبدأ بـ`model` و`unique_id` ثم `region` وإحداثيات XYZ وangle وحالة الحركة والـlife state والسرعات والـbuff count وrarity. أما عنصر الإسقاط فيأتي كـspawn فردي قصير، ويحوّله العميل إلى `DropItem3D` متوهج قابل للمس.

حركة الكيان من السيرفر تصل عبر `0xB021`: الوضع `1` يرسل destination region وdestination XYZ وموضع المصدر، والوضع `0` يرسل region وموضع XYZ وangle. العميل يطابق `unique_id` مع كائن الوحش ويستخدم tween قصيرًا لتحديث موقعه.

أضيف إلى الخادم مسار Action بسيط: طلب `0x7074` بجسم `target_unique_id: Int32` و`skill_id: Int32`، ورد `0xB074` بجسم `target_unique_id` و`skill_id` ونجاح العملية وdamage وcurrent HP وdead flag. المعالج يطبق هجومًا فيزيائيًا أساسيًا على Mob محدد، يرسل النتيجة، ويزيل الوحش من قائمة الرؤية عند موته. التحديد نفسه يستخدم `0x7045` ويرد Agent بـ`0xB045` وبـHP الوحش.

أضيف أيضًا مسار التقاط `0x7099` بجسم `item_unique_id: Int32` ورد `0xB099` بجسم المعرف ونجاح العملية و`RefItemID`. للعناصر غير الذهبية يستخدم الخادم `_ADD_ITEM` مع أول خانة متاحة بعد خانة التجهيز، وللذهب يرسل تحديث الذهب المعتاد، ثم يزيل كائن الإسقاط. يحتفظ العميل بالعناصر المؤكدة في `InventoryUI` ولا يزيل الإسقاط الشبكي إلا عند وصول رد نجاح.

الوحوش المحلية التجريبية في `StarterWorld` تستخدم Mangyang procedural لأغراض العرض والاختبار عندما لا يرسل الخادم spawn بعد. عند اتصال Agent، تُضاف الكيانات الشبكية إلى نفس manager وتُعامل بالطريقة نفسها.
